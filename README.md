# MovieLog — React CSR 성능 최적화

영화 7,956개를 검색·정렬하는 앱에서 React와 브라우저의 렌더링을 최적화한 과정을 기록했습니다.

**[공개 데모 보기](https://yjs000.github.io/react-opt-test/)** · **[성능 비교 보고서](docs/PERFORMANCE_REPORT.md)**

## 프로젝트 소개

- **기능:** 영화 목록 조회, 제목 검색, 기본순·제목순·평점순 정렬
- **데이터:** [TMDB](https://developer.themoviedb.org/docs/getting-started) 영화 데이터 7,956개를 `src/data/movies.json`에 저장해 사용
- **실험 구성:** 대량 목록의 렌더링 비용을 관찰하기 위해 페이지네이션을 의도적으로 적용하지 않음

영화 목록은 외부 API를 호출하지 않고 저장소의 JSON에서 불러옵니다. 포스터 이미지는 TMDB 이미지 서버에서 불러옵니다.

## 최적화

| 적용 항목                | 구현 내용                                                                                                                                                   |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 검색 디바운스            | 입력 후 150 ms 동안 추가 입력이 없으면 검색 결과를 갱신합니다.                                                                                              |
| 필터 결과 재사용         | `useMemo`로 영화 데이터와 검색어가 같을 때 필터 결과를 재사용합니다.                                                                                        |
| 정렬 결과 캐시           | 동일한 필터 결과에서 정렬 기준을 전환할 때 이전에 계산한 정렬 결과를 재사용합니다.                                                                          |
| 컴포넌트 메모이제이션    | `MovieList`와 `MovieCard`에 `memo`를 적용해 전달된 props가 같을 때 불필요한 재렌더링을 줄입니다.                                                            |
| 포스터 비율 고정         | 이미지 영역을 2:3 비율로 확보해 이미지 로딩으로 인한 레이아웃 이동을 줄입니다.                                                                              |
| 이미지 지연 로딩         | `loading="lazy"`로 화면에서 멀리 떨어진 이미지의 로딩을 늦춥니다.                                                                                           |
| 화면 밖 렌더링 비용 절감 | `content-visibility: auto`로 화면 밖 카드 내용의 레이아웃·페인트 작업을 브라우저가 생략할 수 있게 합니다. DOM 생성과 React 렌더링 자체를 없애지는 않습니다. |

API로 대체할 수 있게 TanStack Query로 쿼리 캐시를 관리합니다. 현재는 서버의 영향력을 배제하기 위해 JSON데이터를 가져옵니다.
