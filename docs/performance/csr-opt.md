# CSR 최적화 상세 기록

## 1차 확인 사항

1. 초기 로딩이 느려 보이지는 않는다.
2. 초기 로딩 중 긴 작업이 존재한다. 이로 인해 입력 처리가 지연될 수 있다.
3. `aspect-ratio`가 안정적인 역할을 했다.
4. 검색 입력이 버벅거렸고, 입력값을 처리하는 데 많은 시간이 들었다.
5. 초반 렌더링 비용이 컸다. 검색어를 입력할 때마다 커밋 시간이 362.5 ms → 202.1 ms → 29 ms 등으로 변했다. 처음에는 그릴 것이 많기 때문이다. 이후에는 필터링으로 React 계산, 재조정, 커밋할 내용 등이 줄어들어 렌더링 비용이 점점 작아진다.
6. Bottom-up에서 확인한 결과, DOM을 계산하고 그리는 데에도 오랜 시간이 걸렸다. JavaScript 작업뿐만 아니라 브라우저 작업도 오래 걸렸다.
7. 한 글자를 입력할 때마다 필터링 결과를 계산하고, 이에 따라 DOM을 다시 그리므로 오래 걸릴 것으로 예상된다.

## 1차 해결 방향

1. `memo`, `useCallback` 등의 최적화를 시도한다. `MovieCard`의 내용은 변하지 않지만, 객체가 계속 재생성되고 있다.
2. 이미지 지연 로딩을 사용한다.
3. `SearchBar`에 디바운스를 적용한다.

## 2차 확인 사항

1. 필터링 결과와 필터링된 데이터의 옵션별 정렬 결과를 캐싱했다. 데이터 배열은 메모이제이션했지만 JSX는 메모이제이션하지 않았다. 컴포넌트는 계속 다시 렌더링된다.
2. 데이터양이 많아서 여전히 느린 감이 있다.
3. `SearchBar` 디바운스는 비교 실험 결과 300 ms보다 150 ms의 효과가 더 좋았다.

## 2차 해결 방향

1. `MovieList` 컴포넌트에 `memo`를 적용한다.
2. 현재 스크롤 위치에서 보이는 항목만 먼저 로딩한다.
3. `SearchBar` 디바운스를 150 ms로 조정한다.
